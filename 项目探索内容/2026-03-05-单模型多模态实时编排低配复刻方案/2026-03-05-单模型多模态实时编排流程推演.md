# 2026-03-05 单模型多模态实时编排流程推演（低配复刻版）

## 1. 目标与边界

### 1.1 目标

在“本地 ASR + 远端单多模态模型（统一端点）+ 本地 TTS”的约束下，复刻接近实时多模态对话体验：

1. 普通语音问答走低成本低延迟路径（仅文本）。
2. 视觉相关问题按需注入视频缓存（关键帧 + 时间摘要）。
3. 支持自然打断（barge-in）、顺序指代（第一个/第二个）、结果过期丢弃（stale discard）。

### 1.2 非目标

1. 不追求“每秒重视觉推理”。
2. 不依赖双模型拆分（Instruct + VL），统一使用一个多模态模型端点。

## 2. 术语约定

1. `Instruct`：统一多模态模型的文本推理能力（text-only 路径）。
2. `Vision-Augmented`：统一多模态模型的图文推理能力（text + frames 路径）。
3. `slot`：展示事件槽位，用于承载“第 N 个展示物”的时序记忆。
4. `turn`：一次语音回合（VAD 结束后形成）。
5. `person_hit`：视频中命中本地人物库后的结构化事件。

## 3. 总体架构

```text
Mic ----> VAD ----> ASR ----> Orchestrator ----> MultiModal Model ----> TTS ----> Speaker
                               ^       |
Camera -> Frame Sampler -> RingBuffer  |
                               |       v
                         Slot Builder / Vision Cache
```

关键原则：

1. 默认 `text_only`，仅在视觉意图命中时切换到 `vision_augmented`。
2. 语音优先级高于视觉任务。
3. 所有事件统一时间轴（`session_id + turn_id + monotonic_ts_ms`）。

## 4. 端到端流程推演（逐步）

### Step 1：音频采集与回合切分

流程：

1. 麦克风 20ms 分片输入。
2. VAD 检测 `speech_start/speech_end`。
3. ASR 输出 `partial/final`，`final` 作为回合提交文本。

技术关键点：

1. `partial` 只用于前端字幕，不进入持久语义记忆。
2. `final` 必须带 `start_ts_ms/end_ts_ms`（相对会话单调时钟）。
3. VAD 端点检测建议双阈值，减少误切句。

### Step 2：视频缓存与事件化记忆

流程：

1. 摄像头常态采样 `0.5~1 fps`。
2. 帧写入 `5~10s` 环形缓存。
3. 检测到展示动作/指示语（如“看看这个”）时，临时升采样到 `3~5 fps` 持续 `1~2s`。
4. 基于该时间窗生成或更新 `slot`。
5. 并行做人脸识别，命中人物库则生成 `person_hit`。

技术关键点：

1. 单帧仅有 `frame_ts_ms`，`start/end` 是 `slot` 事件范围，不是帧范围。
2. `slot` 建议字段：
   - `slot_index`
   - `ts_start_ms/ts_end_ms`
   - `keyframes[]`
   - `coarse_objects[]`
   - `confidence`
3. 相似帧去重，避免重复喂模态图像。
4. `person_hit` 建议字段：
   - `person_id/display_name`
   - `face_confidence`
   - `first_seen_ms/last_seen_ms`
   - `track_duration_ms`
5. 建议使用“双阈值 + 连续帧确认”：如 `face_confidence >= 0.82` 且连续 `>=3` 帧再判定命中。

### Step 3：编排层路由决策（提交模型前）

流程：

1. `ASR final` 到达后，先进入编排层意图判定。
2. 判定是否视觉相关：
   - 显式视觉问题（这是什么、第二个是什么、刚才那个是什么）。
   - 顺序指代（第一个/第二个/上一个）。
   - `person_hit` 是否满足自动注入策略。
3. 产出 `route = text_only | vision_augmented`。

技术关键点：

1. 这一步必须在调用模型前完成，避免多一跳延迟。
2. 优先规则判定，必要时再加轻量分类器，不要主路每轮问大模型。
3. 人物库命中属于确定性结构化信号，不依赖大模型判定“是否命中”。

### Step 4：上下文组装

流程：

1. `text_only` 路径：只提交本轮文本 + 必要会话短记忆。
2. `vision_augmented` 路径：
   - 提交本轮文本
   - 提交 `slot` 命中的关键帧（建议 4~6 帧）
   - 提交时序元数据摘要（近 5~10s 的 `slot_index/ts_range/用户指示语`，不依赖预先视觉语义）
   - 若存在 `person_hit`，注入当前命中人物卡片（姓名、关系、互动约束）

技术关键点：

1. 不提交全量缓存帧；使用关键帧选择（固定步长 + 场景变化 + 清晰度过滤）。
2. 视觉内容加 `stale_after_ms`，超时即丢弃。
3. 顺序指代优先查 slot，再做补充推理。
4. 若问题复杂且首轮不确定，可二段式：同一多模态模型先输出结构化视觉摘要，再基于摘要回答。
5. 人物注入坚持“最小化原则”：只注入当前命中人物，禁止整库注入。

### Step 5：模型推理与两阶段答复

流程：

1. 视觉路径先返回回执：`我在看，稍等一下。`（<500ms）。
2. 模型返回最终文本后进入 TTS。

技术关键点：

1. 两阶段答复显著改善体感延迟。
2. 若 VL 路径超时，给降级回复：`我没看清，能再展示一次吗？`。

### Step 6：TTS 播放与打断

流程：

1. TTS 按 `response_id` 队列播放。
2. 监听用户再次开口（VAD `speech_start`）。
3. 一旦 barge-in：立即停播、清空队列、取消当前任务、开启新 turn。

技术关键点：

1. 打断优先级最高，不能等待当前句播完。
2. 被打断的视觉结果即使返回，也按 stale 规则丢弃或仅记日志。

## 6. 状态机（最小可用）

状态：

1. `LISTENING`
2. `THINKING`
3. `SPEAKING`
4. `INTERRUPTING`

事件：

1. `ASR_FINAL`
2. `MODEL_REPLY_READY`
3. `VAD_SPEECH_START`
4. `TTS_DONE`
5. `TASK_TIMEOUT`

核心转移：

1. `LISTENING + ASR_FINAL -> THINKING`
2. `THINKING + MODEL_REPLY_READY -> SPEAKING`
3. `SPEAKING + VAD_SPEECH_START -> INTERRUPTING -> LISTENING`
4. `THINKING + TASK_TIMEOUT -> SPEAKING(降级答复) -> LISTENING`

## 7. 路由规则（建议落地参数）

1. 默认路由：`text_only`。
2. 命中词触发视觉：`这是什么|第[一二三]个|刚才那个|屏幕上写了什么|你看到什么`。
3. 视觉调用冷却：`8~15s`。
4. 单次视觉帧上限：`VLM_MAX_FRAMES = 6`。
5. 视觉结果新鲜度：`stale_after_ms = 6000`。
6. 人物自动注入冷却：同一 `person_id` 在 `30~60s` 内不重复注入。
7. 人物自动注入仅在“用户未讲话且不打断主语音回复”时触发。

## 8. 失败处理与降级

1. 视觉超时：回退 text-only，并要求用户重展示。
2. slot 缺失：明确提示“我没记录到第二个展示物，请再展示一次”。
3. ASR 不确定：优先确认问题再调用视觉，避免误成本。
4. 网络抖动：保留最近一次可用 slot，禁止重复深度调用风暴。
5. 人脸误识别：低置信或短时出现只记日志，不进入推理上下文。

## 9. 关键监控指标

1. `P50/P95 TTFT`
2. `P95 首音时间`
3. `barge_in_success_rate`
4. `vision_route_hit_rate`
5. `vision_timeout_rate`
6. `stale_discard_rate`
7. `avg_cost_per_min`

## 10. 实施顺序（建议）

1. M1：`ASR -> text_only -> TTS` 稳定闭环。
2. M2：加入编排层路由与状态机（含打断）。
3. M3：加入视频缓存 + slot 构建 + 视觉按需注入。
4. M4：补齐超时降级、成本闸门、指标看板与压测。

---

这套方案的核心不是“每秒做重视觉推理”，而是“持续采样做时间化记忆，按需调用视觉能力”。在成本可控前提下可最大化接近实时多模态对话体验。
