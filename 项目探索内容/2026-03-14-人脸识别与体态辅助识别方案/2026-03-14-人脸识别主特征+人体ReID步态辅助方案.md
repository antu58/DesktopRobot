# 2026-03-14 人脸识别主特征 + 人体 ReID/步态辅助方案

更新时间：2026-03-14  
状态：可进入开发

## 1. 目标与边界

目标：

1. 以人脸识别作为主特征，支持 `1:1 验证` 与 `1:N 检索`。
2. 以人体 ReID（可选步态）作为辅助特征，在远距离、遮挡、侧脸或背脸时提高稳定性。
3. 输出系统内部唯一 `person_id`，业务侧只认 `person_id`，不直接把生物特征当主键。

边界：

1. 不追求司法级“绝对唯一”，目标是工程可用的高置信识别。
2. 不含公开场景大规模跨域追踪；先在固定摄像头/固定环境闭环。
3. 步态作为二阶段增强能力，MVP 先做人脸 + ReID。

## 2. 总体架构

```text
摄像头视频流
  -> 目标检测/跟踪（person + face）
  -> 特征提取
      - Face Embedding（主）
      - Body ReID Embedding（辅）
      - Gait Embedding（可选，辅）
  -> 候选召回（向量库）
  -> 分数融合与决策
  -> 输出 person_id + confidence + evidence
```

关键原则：

1. 主从策略：优先人脸，人体 ReID/步态用于补强与歧义消解。
2. 证据可解释：保留每次识别的 face/body/gait 单项分数与最终融合分。
3. 可回滚：每个模块有开关，随时退回人脸单模态。

## 3. 识别流程设计

## 3.1 注册（Enrollment）

1. 每个用户采集 10~20 张脸图（含正脸、侧脸、不同光照）。
2. 同时采集 5~10 秒站立/行走短视频，抽取 body/gait 特征。
3. 生成并存储：
   - `face_template`（推荐 3~5 个中心向量）
   - `body_template`（推荐 2~3 个中心向量）
   - `gait_template`（可选 1~2 个中心向量）
4. 绑定唯一 `person_id`。

## 3.2 在线识别（Recognition）

1. 按帧检测 `person` 与 `face`，并做多目标跟踪（track_id）。
2. 若检测到可用脸图：执行 face 特征提取 + 1:N 检索。
3. 若脸图质量差或缺失：执行 body ReID 检索；步态窗口满足时补充 gait 检索。
4. 融合多模态分数，输出候选 `top1/topk`。
5. 若融合分数低于阈值，标记为 `unknown`，不强判。

## 3.3 1:1 验证

1. 输入 `claimed_person_id` + 当前特征。
2. 对该 ID 模板计算相似度并融合。
3. 返回 `accept/reject` + `confidence` + 各模态证据。

## 4. 模型与组件建议（成熟优先）

## 4.1 人脸主链路

1. 人脸检测：`SCRFD` 或 `RetinaFace`。
2. 人脸特征：`ArcFace`（InsightFace 生态成熟）。
3. 活体检测（推荐加）：轻量二分类模型（RGB 活体），防照片/视频攻击。

## 4.2 人体 ReID 辅链路

1. 人体检测：`YOLOv8/YOLO11 person`。
2. 跟踪：`ByteTrack` 或 `BoT-SORT`。
3. ReID 特征：`OSNet` 或 FastReID 的常用骨干（稳定、资料多）。

## 4.3 步态（可选增强）

1. 方案：`OpenGait` 生态（如 GaitSet/GaitGL）。
2. 使用条件：同一 track 里有连续行走窗口（建议 >= 20~30 帧）。
3. 仅作为辅助分数，不单独决定身份。

## 5. 分数融合与判定

定义：

- `S_face`：人脸相似度
- `S_body`：ReID 相似度
- `S_gait`：步态相似度（可选）

建议初始融合：

`S_final = 0.70*S_face + 0.25*S_body + 0.05*S_gait`

动态权重：

1. 若无可用脸图：`S_final = 0.80*S_body + 0.20*S_gait`。
2. 若仅 face 可用：`S_final = S_face`。
3. 若 track 很短（步态不稳定）：`gait` 权重设为 0。

阈值策略（先验起步，后续按验证集调）：

1. `T_accept`：高置信通过阈值。
2. `T_review`：介于 `T_review` 和 `T_accept` 返回“低置信命中”。
3. `< T_review`：返回 `unknown`。

## 6. 数据与存储设计

## 6.1 表结构（最小）

1. `person_profile`
   - `person_id` (PK)
   - `display_name`
   - `status`
   - `created_at`
2. `biometric_template`
   - `template_id`
   - `person_id`
   - `modality` (`face`/`body`/`gait`)
   - `embedding` (vector)
   - `quality_score`
   - `created_at`
3. `recognition_event`
   - `event_id`
   - `track_id`
   - `top1_person_id`
   - `s_face`
   - `s_body`
   - `s_gait`
   - `s_final`
   - `decision` (`accept/review/unknown/reject`)
   - `frame_ts`

## 6.2 向量检索

1. 小规模可先用 `pgvector`。
2. 数据量上来后可切 `Milvus/FAISS`。
3. 不同模态建议分集合索引，避免混检。

## 7. API 约定（MVP）

1. `POST /v1/biometric/enroll`
   - 输入：`person_id`、face/body/gait 样本
   - 输出：模板写入结果
2. `POST /v1/biometric/identify`
   - 输入：当前帧/track 特征
   - 输出：`topk`、`s_face/s_body/s_gait/s_final`、`decision`
3. `POST /v1/biometric/verify`
   - 输入：`claimed_person_id` + 当前特征
   - 输出：`accept/reject` + 置信度

## 8. 开发里程碑（2 周）

## Week 1（MVP）

1. 打通 `face detect -> face embedding -> 1:N 检索`。
2. 打通 `person detect + track -> body ReID -> 1:N 检索`。
3. 完成分数融合与 `accept/review/unknown` 判定。
4. 完成 `enroll/identify/verify` 三个接口。

## Week 2（增强）

1. 引入活体检测与质量评估（模糊、遮挡、侧脸角度）。
2. 增加步态辅助分支（可开关）。
3. 做阈值校准（ROC/PR、FAR/FRR）与误识别回放。
4. 上线灰度：只读模式对比人工结果后再放开自动判定。

## 9. 验收指标（建议）

1. `1:N top1 accuracy`（白天/夜间分别统计）。
2. `FAR`（误认率）与 `FRR`（拒真率）。
3. 遮挡场景下引入 ReID 后的召回提升。
4. 单帧平均耗时与端到端时延（目标可先定 <= 300ms/人，按设备调）。

## 10. 风险与控制

1. 同卵双胞胎/高度相似外观：可能误认，必须保留 `review/unknown` 分支。
2. 低光、背光、运动模糊：显著影响 face 分支，需依赖 body/gait + 质量门控。
3. 隐私合规：模板向量加密存储、最小化保留原图、提供删除与审计能力。

## 11. 对当前需求的直接结论

你当前提出的能力（人脸主特征 + 人体 ReID/步态辅助）可以按上面方案直接开工：

1. 先上 `face + ReID` 的双分支 MVP，满足多数工程场景。
2. 再补 `gait` 作为困难场景增强。
3. 统一输出 `person_id`，把“唯一性”落在系统 ID 层，而非单一生物特征层。
